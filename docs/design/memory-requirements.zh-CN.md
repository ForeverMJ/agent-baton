# 需求：多 Agent 共享的个人记忆（个人助理场景）

> 状态：需求整理稿（2026-10-27），待确认后进入设计。

## 1. 一句话

我在本机同时用 Claude Code、Codex、opencode 当个人助理。**在任何一个 agent 里说过的事、做过的决定，
其它 agent 下次打开时也应该知道**，像在和同一个助理说话。

## 2. 为什么现在的 baton 不够

baton 解决的是**编程接力**：按项目（git 根目录）找会话，生成 `.baton/RESUME.md`。个人助理场景有三处根本不同：

| | baton（编程接力） | 本需求（个人记忆） |
|---|---|---|
| 归属 | 项目 / 目录 | **人**（跨所有目录） |
| 共享什么 | 某个任务停在哪 | 我是谁、我在忙什么、我们聊过什么、定了什么 |
| 时间尺度 | 几小时，下一个 agent 接着干 | 几周到几个月，长期积累 |
| 兜底 | git 本身就能同步代码 | 没有兜底，聊完就散 |

本机实际数据（只读扫描）也说明了这一点：

- **会话目录是一次性的。** Codex 桌面版的新对话在 `~/Documents/Codex/<日期>-<主题>/`；
  Claude 桌面版的会话在 `AppData/.../Claude/scratch-workspaces/.../scratch-<日期>-<随机>/`。
  （初稿里"17 个会话"的统计漏掉了 Codex 压缩存档的 `.jsonl.zst`，实际有 186 个 Codex 会话。）
  每开一个新对话就是一个新目录，**按目录匹配根本找不到"上次聊的"**。
- **连单个 agent 自己都不记得。** Claude Code 的记忆按目录存，`~/.claude/projects/` 下有 21 个 `memory/`
  目录，聊天类目录里总共只有 2 个记忆文件，彼此看不到；Codex 的 `~/.codex/memories/` 是空的。
- 所以问题不只是"agent 之间不连通"，而是**个人助理类对话本来就没有一个按人归属的记忆层**。

## 3. 典型场景

1. **跨 agent 延续话题**：在 Codex 里聊了 PhD 申请的选校思路；第二天在 Claude Code 里说"继续昨天的选校"，
   它知道是哪几所、卡在哪一步。
2. **偏好只说一次**：在任意 agent 里说过"邮件用日语敬语、署名 Zion"，之后所有 agent 写邮件都照做。
3. **决定不被推翻**：在 opencode 里定了"旅行预算 15 万日元以内"，换到 Claude 里规划时不会重新问或给出超预算方案。
4. **回溯**："我上周在哪个 agent 里聊过 XX？当时结论是什么？" 能查到并给出原会话出处。
5. **额度用完换 agent**（个人助理版的 baton）：Codex 写到一半没额度了，换 Claude 能直接接着写那封邮件/那份计划。

## 4. 要共享的内容（分层）

| 层 | 内容 | 例子 | 变化频率 | 默认注入？ |
|---|---|---|---|---|
| L1 个人档案 | 稳定事实与偏好 | 身份、语言习惯、写作风格、常用工具 | 很少 | 是（常驻，小） |
| L2 进行中的事 | 话题/事务的当前状态、已定的决定、下一步 | "PhD 申请：已定 3 所，下一步写 SOP" | 每天 | 是（只注入活跃的，摘要） |
| L3 会话日志 | 每个会话一条：哪个 agent、何时、聊了什么、结论 | "10-26 Codex：比较了 A/B 两所学校" | 每次会话 | 否，按需检索 |
| L4 原文 | 各 agent 自己的 transcript | — | — | 否，按需定位（不复制） |

原则：**注入的要少而准（L1+L2），其余靠检索**。上下文窗口是稀缺资源。

## 5. 功能需求

**采集（读）**
- F1 只读地发现并解析三个 agent 的所有会话，**不限于项目目录**（复用 baton 现有 adapter）。
- F2 支持 Windows + WSL 两侧（复用 baton 的 env 机制）。
- F3 增量处理：只处理新增/更新的会话。

**沉淀（写入记忆）**
- F4 把会话沉淀为 L3 日志条目，并更新相关 L2 话题、必要时更新 L1 档案。
- F5 每条记忆带出处：agent、会话 id、时间（可回溯到原文）。
- F6 Agent 也能主动写记忆（"记住：……"），任何 agent 写入的都对其它 agent 可见。

**使用（读出）**
- F7 ~~新会话开始时自动注入 L1 + 活跃 L2 的简短摘要~~。2026-10-28 修订：**只在需要时增加上下文**。开局默认只注入
  L1 档案（可配置为全量或不注入）；L2、L3 在用户的消息涉及过去或自己的计划、偏好时才检索并附上
  （设计 4.3）。
- F8 会话中可按需检索：按关键词/时间/话题/agent 查 L2、L3，并能拿到原文片段。
- F8a（2026-10-28）尽可能多地互通：编程项目里的会话也参与按需取回；日志记下每个用户请求，而不只是首尾两条。
  首选做成一个三家都能用的 **MCP server**（Claude Code、Codex、opencode 都支持 MCP），CLI 作为兜底。
- F9 在三家的全局指令文件里写一段规则，告诉 agent 何时查、何时写
  （`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.config/opencode/AGENTS.md`）。

**管理（人）**
- F10 记忆是人能直接读、能直接改的纯文本（Markdown），放在一个固定目录（如 `~/.baton/memory/`）。
- F11 能看、改、删任何一条；能"忘掉"某个话题或某段时间。
- F12 能排除某些会话/目录不进记忆（例如纯编程项目，或敏感对话）。

## 6. 非功能需求

- 全部本地、离线可用，不把内容发到任何外部服务。
- 对各 agent 的数据**只读**，绝不改写它们的文件（沿用 baton 规则）。
- 不阻塞、不拖慢 agent：注入在 1 秒内完成，失败时静默跳过。
- 写入前脱敏（复用 baton 的 redaction），不存 token、密码、卡号。
- 零运行时依赖，Node ≥ 22.5（与 baton 一致）。
- 多个 agent 同时运行时写记忆不冲突、不丢失（文件锁或追加写）。

## 7. 需要拍板的问题

1. **谁来做"沉淀"（把聊天变成记忆）？** 这是最关键的一点。
   - A. **agent 自己写**：规则要求每个 agent 在会话里遇到值得记的东西就调用 `memory.write`，结束前更新话题状态。
     零成本、语义准；但依赖 agent 自觉，可能漏记。
   - B. **规则提取**（baton 现有做法，不调 LLM）：能可靠得到 L3"聊了什么"的骨架（用户原话、最后结论），
     但提炼不出"偏好""决定"。
   - C. **后台调用 LLM 提炼**：效果最好，但要花额度/需要 API key，且额度耗尽时正是最需要它的时候。
   - 建议：**A + B**。B 保证每个会话至少留下一条日志不会漏，A 负责高质量的偏好和决定；C 以后作为可选项。
2. **话题（L2）怎么划分？** 由 agent 写入时指定话题名，还是工具自动聚类？建议先由 agent 指定 + 人可合并。
3. **范围**：只管个人助理类会话，还是编程会话也进记忆？建议默认都进 L3 日志，但编程会话不自动更新 L1/L2；
   编程的接力仍由现有 `.baton/` 负责。
4. **与各 agent 自带记忆的关系**：一次性导入 Claude 已有的 `memory/` 文件，之后以共享记忆为准？
5. **范围外**（先不做）：claude.ai / ChatGPT 网页端（数据不在本地）、多台机器之间同步、多用户。

## 8. MVP 与验收

MVP：
- 共享记忆目录（L1 `profile.md`、L2 `topics/*.md`、L3 `log/<日期>.md`）
- 规则提取生成 L3 日志（B）
- MCP server：`memory.search` / `memory.read` / `memory.write`
- SessionStart 注入 L1 + 活跃 L2
- 三家全局指令文件里的规则段落（`baton install` 一并写入）

验收标准（用真实 agent 跑通）：
- 在 Codex 里说"记住我下周三去大阪出差"，关掉；打开 Claude Code 问"我下周有什么安排"，答得出来并注明来自 Codex。
- 在 opencode 里定下一个决定，在 Codex 里提出相反方案时，它会提醒之前的决定。
- 问"我上周在哪聊过 PhD 选校"，能列出会话（agent + 时间）和结论。
