# 共有メモリ

[English](../shared-memory.md) · [中文](../zh-CN/shared-memory.md) · 日本語

あなたについてのひとつのメモリを、すべてのエージェントが、どのフォルダーからでも共有します。このページでは、
メモリに何が入るのか、エージェントがそれをどう使うのか、そして自分でどう扱えるのかを説明します。

## 何が記憶されるか

メモリは `~/.config/baton/memory/` にあり、4 つの層で構成されます。

| 層 | ファイル | 内容 | 書き込む主体 |
|---|---|---|---|
| プロフィール | `profile.md` | あなたの好みや、あなたに関する事実 | エージェント（`memory_remember`）、またはあなた |
| トピック | `topics/<name>.md` | 取り組んでいる物事ごとの、現在の状況・決定・次のステップ・履歴 | エージェント、またはあなた |
| ジャーナル | `journal/<date>.md` | 各エージェントでの会話 1 件につき 1 エントリ | baton が自動で |
| トランスクリプト | エージェント自身のファイル | 会話の全文 | コピーはせず、必要に応じて読み取る |

### プロフィールとトピック：エージェントが残すと判断したもの

エージェントは短い文を 1 つずつ保存します。種類は次の 5 つです。

| 種類 | 保存先 | 例 |
|---|---|---|
| `preference` | プロフィール | 「メールは丁寧な日本語で書き、署名は Zion」 |
| `fact` | プロフィール | 「大学院生で、博士課程への出願を予定している」 |
| `status` | トピック | 「博士課程出願：3 校に絞り込み、SOP を執筆中」 |
| `decision` | トピック | 「米国とカナダのプログラムに限定する」 |
| `next` | トピック | 「金曜までに SOP の草稿を指導教員に送る」 |

- トピックが持つ**現在の状況は 1 つだけ**です。新しい状況を保存すると、古いものは *History*（履歴）に移ります。
- 決定が覆されたときは、エージェントが `replaces: m:<id>` を渡します。古い項目は取り消し線付きで *History* に移されるので、
  黙って上書きされることはなく、変更の経緯が見える形で残ります。
- トピック名はゆるく照合されます（「PhD出願」「phd 出願」「PhD-出願」は同じトピック）。そのため、エージェントは重複した
  トピックを作らず、既存のトピックに追記します。

各項目には、ID、日付、出どころのエージェントが非表示のコメントとして記録されます。

```markdown
## Preferences
- Writes emails in polite Japanese, signed Zion <!-- m:k3f9 2026-10-27 codex -->
```

### ジャーナル：すべての会話が残すもの

エージェントは保存し忘れることがあるため、baton は自分でもジャーナルを書きます。内容は決まったルールに従って
トランスクリプトからコピーされます（モデルは使いません）。

```markdown
### 14:05 · codex · Compare PhD programs
- desktop chat · 12 turns · 10-26 14:05–15:20
- First: "Compare the PhD programs of A and B…"
- Last request: "Rank them in that order"
- Last reply: "Here is the ranking: 1. A …"
- Remembered: m:b7d1, m:d2a8
```

ジャーナルには、会話が行われた場所、最初と最後の依頼（それぞれ最大 200 文字）、最後の返答（最大 400 文字）、
そしてその会話で保存されたメモリ項目が記録されます。ツールの出力、コマンドの出力、ファイルの内容は一切保存せず、
シークレットは伏せ字にします。

ジャーナルに記録されないもの：

- プログラムが開始したセッション（`codex exec`、`claude -p`、`opencode run`、エージェントを組み込んだアプリ）。
  含めたい場合は、メモリの `config.json` で `"includeHeadless": true` を設定します。
- `"exclude"` に列挙したフォルダー内のセッション。
- エージェントが一度も応答しなかったセッション（ログインの失敗、最初のプロンプトでの利用上限エラーなど）。
- クラウドにしか保存されない会話（Claude デスクトップアプリの Chat タブ、ChatGPT）。

## エージェントの使い方

**セッションの開始時**には、フックがエージェントにサマリーを渡します（`baton mem brief` で確認できます）。

- プロフィール全体（最大 1,500 文字）
- 過去 14 日以内に更新されたアクティブなトピック最大 5 件と、その状況・最新の決定・次のステップ
- 過去 3 日以内の最近の会話最大 5 件（どのエージェントでも可、コーディングプロジェクトは除く）
- いつ保存し、いつ調べるべきかについての数行

サマリーは約 3,000 文字が上限で、ジャーナルが会話を引用しているため、*指示ではなくデータ* として渡されます。
フックを持たないエージェントは、`memory_context` を呼び出して同じサマリーを受け取ります。

**セッション中**、エージェントは 5 つの MCP ツールを使います。

| ツール | 役割 |
|---|---|
| `memory_context` | セッション開始時のサマリー |
| `memory_search` | プロフィール、トピック、ジャーナルを検索。すべての語が一致する必要があり、中国語と日本語は部分一致でもヒットする |
| `memory_read` | トピック全体、または過去の会話を読む。`transcript: true` を指定すると、その会話のユーザーとアシスタントのメッセージをすべて読める |
| `memory_remember` | 項目を 1 つ保存する（種類は上記のとおり） |
| `memory_forget` | 項目を削除する、または会話をジャーナルから完全に取り除く |

各エージェントのグローバル指示にあるルールブロックは、あなたが好み、自分に関する事実、決定を述べたとき、
作業の状況や次のステップが変わったとき、あるいは「覚えておいて」と言ったときに保存するよう指示します。
また、以前の会話に触れたときや、あなた自身の予定について尋ねたときには検索するよう指示します。
Codex はこれらのツールを自動で承認しますが、`memory_forget` だけは実行前にあなたに確認します。

**出どころのラベル。** 項目とジャーナルのエントリには、それを生成したエージェント（`claude`、`codex`、`opencode`、
WSL 内のエージェントなら `claude@wsl:Ubuntu`）が記録されるので、どの記憶がどこから来たのかを常に確認できます。

## 自分で扱う

ファイルはただの Markdown です。開いて行を編集したり、削除したりできます。手で追加した箇条書きには、
次にエージェントがそのファイルに書き込むときに ID が付与されます。

```bash
baton mem show                       # プロフィールとトピックの一覧
baton mem show "PhD applications"    # 1 つのトピック
baton mem search osaka trip          # すべてを検索
baton mem add preference "Short answers, no small talk"
baton mem add decision "Fly instead of taking the train" --topic "Osaka trip" --replaces m:zxn8
baton mem forget m:zxn8              # 項目を 1 つ削除
baton mem forget --session codex:019a   # 会話をジャーナルから完全に取り除く
baton mem sync --all                 # 全履歴をジャーナルに記録（過去 30 日分だけでなく）
```

## 制限事項

- サマリーが渡されるのはセッション開始時の一度だけです。すでに実行中のセッションは、その後に別のエージェントが
  保存した内容を、検索しない限り知りません。
- 保存はエージェントがルールに従うかどうかに左右されるため、取りこぼすことがあります。ジャーナルには会話が必ず
  記録されますし、*「覚えておいて：…」* と言えば確実です。
- クラウドにしか存在しない会話はジャーナルに記録されません。ただし、それらのアプリもツールを通じてメモリの
  読み書きはできます。
- ジャーナルが保持するのは抜粋です。会話の全文は必要に応じてエージェント自身のファイルから読むため、
  エージェントが履歴を削除すると読めなくなります。
