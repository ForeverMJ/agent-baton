# プライバシーとトラブルシューティング

[English](../faq.md) · [中文](../zh-CN/faq.md) · 日本語

## プライバシー

**何かがマシンの外に出ることはありますか？** いいえ。baton がモデル、API、その他のネットワークサービスを呼び出すことは
ありません。メモリはホームディレクトリにある Markdown ファイルのフォルダーです。

**baton は何を読み取りますか？** エージェントのローカルのトランスクリプトとセッションデータベースです。Claude Code の
`~/.claude/projects/`、Codex の `~/.codex/sessions/`、opencode の `opencode.db` です。opencode のデータベースからは
session、message、part、todo の各テーブルだけを読み取り、認証情報を保持するテーブルは決して読みません。

**エージェントのデータを変更しますか？** 一切しません。書き込むのは [リファレンス](reference.md#files-baton-writes) に
記載したファイルだけです。つまり、自身のメモリフォルダー、各エージェントの設定とグローバル指示内のマーク付きエントリ
またはブロック 1 つ（各ファイルは事前にバックアップ）、そして `baton init` を実行したプロジェクトの `.baton/` です。

**メモリには何が入りますか？**
- エージェント（またはあなた）が意図的に保存した項目：好み、事実、決定、状況についての短い文。
- 会話ごとのジャーナルエントリ：最初と最後の依頼、最後の返答、その会話で保存された項目。ツールの出力、コマンドの出力、
  ファイルの内容は決して含みません。
- API キー、トークン、JWT、秘密鍵、`password=…` 形式の代入、URL 内の認証情報などに見えるシークレットは、書き込む前に
  `[REDACTED]` に置き換えられます。これはベストエフォートです。一般的でない形で入力されたシークレットについては
  頼りにしないでください。

**エージェントはこれを通じて会話の全文を読めますか？** はい、要求があれば読めます。`memory_read` に
`transcript: true` を指定すると、ジャーナルに記録された会話のユーザーとアシスタントのメッセージ（ツールの出力は除く）が
返されます。これが、あるエージェントで始めた作業を別のエージェントが続けられる仕組みです。特定の会話を除外するには
`baton mem forget --session <agent:id>` で削除し、フォルダー全体を除外するには `exclude` に追加してください。

**メモリは指示としてエージェントに渡されますか？** いいえ。サマリーは指示ではなくメモとして渡されます。ジャーナルは
会話を引用しているため、そうしないと、エージェントが読んだ Web ページやファイルから紛れ込んだテキストを
運んでしまうおそれがあるからです。

**すべてを削除するには？** `baton uninstall` を実行し、`~/.config/baton/` を削除してください。

## トラブルシューティング

**Codex がセッション開始時にサマリーを受け取らない。** Codex は信頼（trust）したフックしか実行しません。
`codex` を起動して `/hooks` と入力し、baton のエントリを信頼してください。信頼はフックの正確な内容に結び付いているため、
`baton install` が `codex hooks updated` と表示したら、もう一度信頼し直してください。それまでの間も Codex は
メモリツールを使えます。

**エージェントがメモリを認識していないようだ。** エージェントを再起動してください。エージェントは起動時に MCP サーバーと
グローバル指示を読み込みます。デスクトップアプリはウィンドウを閉じるだけでなく、完全に終了（トレイアイコンから）する
必要があります。そのうえで、エージェントが baton を認識しているか確認してください。`claude mcp list`、`codex mcp list`、
`opencode mcp list` のそれぞれで、baton が接続済みと表示されるはずです。

**伝えたことをエージェントが保存しなかった。** 保存するかどうかはエージェント次第なので、取りこぼすことがあります。
確実に残すには *「覚えておいて：…」* と言ってください。いずれにせよ、その会話はジャーナルに残っています。

**エージェントは本当にメモリを使ったのか？** `~/.config/baton/memory/memory.log` の末尾を見てください。
ツールの呼び出しはそれぞれ `mcp: <client> (<agent>) called <tool>: ok` という形で、内容を含めずに記録されます。

**Claude デスクトップアプリの Chat タブで baton を使えない。** `baton install claude-desktop` を実行し、アプリを
完全に終了してから再度起動し、初めて確認されたときに baton のツールを許可してください。

**ずっと前の会話が見つからない。** `baton mem init` がジャーナルに記録するのは過去 30 日分です。
全履歴を記録するには `baton mem sync --all` を実行してください。

**Codex の会話が見当たらない。** Codex は古いセッションを圧縮しています。それを読むには Node.js 22.15 以降が必要です。

**ジャーナルにない会話がある。** プログラムが開始した会話（`includeHeadless` を設定しない限りスキップ）、除外したフォルダー
内の会話、あるいはまったく返答のなかった会話である可能性があります。`baton mem sync` を実行すると、新しいものは
すぐにジャーナルに記録されます。

**WSL 内のフックが遅い。** Windows から `baton mem share wsl:<distro>` を再度実行してください。ディストリビューション内の
baton のローカルコピーが更新されます。`/mnt/c` から baton を読み込むと遅くなります。

**エラーの出力。** フックがエージェントを失敗させることはありません。問題は `~/.config/baton/memory/memory.log`（メモリ）と
`<project>/.baton/hook.log`（引き継ぎ）に記録されます。コマンドラインでスタックトレースを表示するには
`BATON_DEBUG=1` を設定してください。

それでも解決しない場合は、OS、Node.js のバージョン、エージェントのバージョン、関連するログの行を添えて Issue を作成してください。
