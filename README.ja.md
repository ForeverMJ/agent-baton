# agent-baton

**すべてのコーディングエージェントで共有する、ひとつのローカルメモリ。**
今日 Codex に伝えたことを、明日には Claude Code が知っています。

[English](README.md) · [中文](README.zh-CN.md) · 日本語

AI エージェントを複数使い分けている方は多いでしょう。Claude Code、Codex、opencode、しかも複数の
環境（Windows と WSL）で。それぞれが自分の履歴しか持たないため、ほかのエージェントに伝えたこと、
つまりあなたの好み、昨日下した決定、途中まで進めていた計画を、どのエージェントも知りません。
`agent-baton`（コマンド名は `baton`）は、あなたのマシン上に置かれる共有メモリをエージェントたちに提供します。

- **共有メモリ。** 好み、事実、決定、進行中の作業の状況は、そのとき会話していたエージェントが保存し、
  どのエージェントからも読めます。さらにすべての会話が検索可能なジャーナルに記録されるので、
  エージェントは別の場所で話した内容を調べられます。
- **引き継ぎ（ハンドオフ）。** 作業の途中でエージェントの利用上限に達しても、次のエージェントが
  ちょうど止まったところから再開できます。目標、ToDo リスト、直近のコマンド、失敗、変更されたファイルまで引き継ぎます。
- **ローカルでプライベート。** ホームディレクトリに置かれたただの Markdown ファイルです。クラウドも
  API キーも不要で、baton 自身が LLM を呼び出すこともありません。エージェント自身のデータは読み取るだけです。

```
   Claude Code ─┐                                  ┌─ 「昨日 Codex で旅行について
   Codex ───────┼──▶  ~/.config/baton/memory/  ◀───┤    何を決めたっけ？」
   opencode ────┤     profile · topics · journal   └─ Claude Code が Codex の会話を引用して回答
   (also WSL) ──┘
```

## クイックスタート

**Node.js 22.15 以降**が必要です。

```bash
npm install -g https://github.com/ForeverMJ/agent-baton/releases/latest/download/agent-baton.tgz   # `baton` コマンドをインストール
baton mem init                                    # メモリを作成し、過去 30 日分をジャーナルに記録
baton install                                     # Claude Code、Codex、opencode を接続
```

続いて次の手順を行います。

1. エージェントを**再起動**して、baton を読み込ませます。
2. **Codex のみ：** Codex を開いて `/hooks` を実行し、baton のエントリを信頼（trust）します（Codex は
   あなたが確認していないフックを実行しません）。
3. いつもどおりエージェントと会話します。あるエージェントに *「覚えておいて：メールは丁寧な日本語（敬語）で書く。」*
   と伝え、別のエージェントに *「私のメールの書き方の好みは？」* と聞いてみてください。

WSL も使っていますか？ `baton mem share wsl:Ubuntu` で、そのディストリビューションのエージェントも同じメモリにつながります。
詳細と動作確認の方法は [はじめに](docs/ja/getting-started.md) を参照してください。

## 仕組み

| 内容 | 情報源 | エージェントの使い方 |
|---|---|---|
| **プロフィール**：あなたの好みや事実 | エージェント（またはあなた）が `memory_remember` で保存 | 各セッション開始時のサマリーに含まれる |
| **トピック**：取り組んでいる物事の状況・決定・次のステップ | エージェントが保存 | アクティブな間はサマリーに含まれる |
| **ジャーナル**：各エージェントでの会話 1 件につき 1 エントリ | ルールに従ってトランスクリプトから自動でコピー | 必要に応じて検索（`memory_search`） |
| **トランスクリプト**：会話の全文 | エージェント自身のファイル（コピーはしない） | 必要に応じて読み取り（`memory_read`） |

`baton install` は各エージェントを 3 つの方法で接続します。5 つのメモリツールを備えた **MCP サーバー**
（`baton mcp`）、いつ保存し、いつ調べるべきかをエージェントのグローバル指示に書き込む短い**ルールブロック**、
そしてセッションをジャーナルに記録し、新しいセッションにサマリーを渡す**フック**です。フックを持たない
エージェント（Claude デスクトップアプリの Chat タブ）も同じツールを使います。

詳しくは：[共有メモリ](docs/ja/shared-memory.md) · [引き継ぎ](docs/ja/handoff.md)

## 対応エージェント

| エージェント | メモリ | 引き継ぎ | 備考 |
|---|---|---|---|
| Claude Code（CLI、デスクトップアプリの Code タブ） | ✓ | ✓ | |
| Codex（CLI、デスクトップアプリ） | ✓ | ✓ | `/hooks` でフックを一度信頼する |
| opencode | ✓ | ✓ | |
| Claude デスクトップアプリの Chat タブ | ✓ ツールのみ | – | チャットはクラウドにあり、ジャーナルには記録されない |
| WSL 内のエージェント | ✓ | ✓ | Windows と同じメモリを共有。[Windows + WSL](docs/ja/windows-wsl.md) を参照 |

Windows 11 と Linux（WSL Ubuntu）で動作確認しています。macOS でも動くはずですが、未検証です。
ほかのエージェントへの対応も歓迎します。それぞれ小さなアダプターを書くだけです（[CONTRIBUTING](CONTRIBUTING.md)）。

## プライバシーの要点

- すべてはあなたのマシン上にとどまります。baton がモデルやネットワークサービスを呼び出すことはありません。
- エージェントのトランスクリプトやデータベースは読み取るだけで、書き込みません。baton が書き込むのは、
  自身のメモリフォルダー、各エージェントの設定とグローバル指示内のマーク付きブロック（事前にバックアップ）、
  そして引き継ぎ用に `baton init` を実行したプロジェクトの `.baton/` だけです。
- ジャーナルにはツールの出力やファイルの内容を一切保存せず、シークレット（API キー、トークン、
  パスワード）は書き込む前に伏せ字にします。
- `baton uninstall` はエージェントの設定に追加したものをすべて削除します。メモリはただの Markdown なので、
  自由に読んだり、編集したり、削除したりできます。

詳しくは [プライバシーとトラブルシューティング](docs/ja/faq.md) をご覧ください。

## ロードマップ

- オンデマンドのメモリ読み込み：セッション開始時にはプロフィールだけを読み込み、トピックや過去の会話は
  メッセージがそれに触れたときに取得する（[設計](docs/design/memory-design.zh-CN.md)（中国語）、4.3 節）
- 対応エージェントの追加：Cursor、Gemini CLI、Cline、Aider
- クラウドのチャット（Claude、ChatGPT）のエクスポートをジャーナルに取り込む
